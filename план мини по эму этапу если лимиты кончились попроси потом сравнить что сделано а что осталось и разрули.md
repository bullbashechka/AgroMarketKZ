Этап 4: Каталог (публичное чтение) — план реализации │
│ │
│ Контекст │
│ │
│ Первая открытая задача Этапа 4 (TASKS.md): три read-точки каталога для Telegram Mini App AgroMarketKZ. БД (миграция 0001*initial_schema.sql) и Zod-контракты (packages/contracts) уже готовы. Бэкенд — Hono + postgres.js, паттерн «route → repo» как в backend/src/routes/profile.ts + backend/src/repos/users.ts. │
│ │
│ Продуктовые решения (утверждены с владельцем): │
│ 1. Каталог виден только зарегистрированным (JWT + заполненные имя/телефон) — API закрыт от парсеров. │
│ 2. Список категорий — все активные, включая пустые (пустое состояние рисует фронт). │
│ 3. Архивная карточка по прямому id отдаётся (с archivedAt) — фронт покажет заглушку «снято с публикации»; из списков и поиска архив исключён. │
│ 4. Поиск — по части названия, без учёта регистра (ilike '%…%'), без fuzzy. │
│ 5. Порядок карточек — админский sort_order, затем title (совпадает с индексом cards_active_catalog_idx). │
│ 6. Пагинация — load-more limit/offset (paginationQuerySchema, paginated() из contracts), цена — целые тенге. │
│ │
│ API (все под авторизацией + регистрацией) │
│ │
│ ┌───────┬────────────────────────────────────────────────────────────────────┬───────────────────┬───────────────────────────────────────────────┐ │
│ │ Метод │ Путь │ Вход │ Ответ │ │
│ ├───────┼────────────────────────────────────────────────────────────────────┼───────────────────┼───────────────────────────────────────────────┤ │
│ │ GET │ /catalog/categories?type= │ categoryListQuery │ categoryListResponse │ │
│ ├───────┼────────────────────────────────────────────────────────────────────┼───────────────────┼───────────────────────────────────────────────┤ │
│ │ GET │ /catalog/cards?type=&categoryId?&search?&priceType?&limit?&offset? │ cardListQuery │ cardListResponse (items, hasMore, nextOffset) │ │
│ ├───────┼────────────────────────────────────────────────────────────────────┼───────────────────┼───────────────────────────────────────────────┤ │
│ │ GET │ /catalog/cards/:id │ uuid в пути │ cardDetailSchema (включая архивные) │ │
│ └───────┴────────────────────────────────────────────────────────────────────┴───────────────────┴───────────────────────────────────────────────┘ │
│ │
│ Контракты уже покрывают всё (catalog.ts, card.ts, category.ts, pagination.ts) — новых схем не нужно, кроме, возможно, экспорта response-алиаса для карточки (проверить, cardDetailSchema уже экспортируется через index.ts). │

│ 4. Middleware регистрации: backend/src/middleware/registered.ts (новый) │

│ requireRegistered — ставится ПОСЛЕ requireAuth; берёт userId из c.get("auth"), одним запросом проверяет users.registered_at is not null, иначе HttpError(403, "Требуется регистрация"). JWT выдаётся до регистрации (см. routes/auth.ts), поэтому проверка по БД, а не по токену. │
│ │
│ 5. Репозиторий: backend/src/repos/catalog.ts (новый) │
│ │
│ По образцу repos/users.ts (интерфейсы Row, getDb(env), маппер в DTO): │
│ - listCategories(env, type) — where type = … and is_active, order by sort_order, name. │
│ - listCards(env, query) — базовые условия type = … and archived_at is null; опционально category_id, title ilike (экранировать %, *, \ в пользовательском вводе — helper escapeLike в этом же файле или lib/), price*type; order by sort_order, title; limit + 1 строк для вычисления hasMore/nextOffset. Первое фото и первая характеристика — left join lateral по sort_order (превью: imageUrl, shortSpec = «ключ: значение»). │
│ - getCardById(env, id) — карточка (включая архивную) + все card_images и card_specs по sort_order (3 простых запроса); undefined → 404. │
│ - Мапперы: цена price_amount → priceAmount (number|null), даты → ISO, storage_path → url через publicImageUrl. │
│ │
│ 6. Маршруты: backend/src/routes/catalog.ts (новый) │
│ │
│ По образцу routes/profile.ts: catalogRoutes.use("\*", requireAuth, requireRegistered); парсинг query через categoryListQuery.parse / cardListQuery.parse (ZodError → 400 общим обработчиком в app.ts); :id валидировать z.uuid() — невалидный uuid → 404 «Карточка не найдена» (не отдавать postgres-ошибку). Подключить в app.ts: app.route("/catalog", catalogRoutes). │

│ Верификация │
│ │
│ 1. bun run typecheck (в backend/) и bun test — зелёные. │
│ 2. Поднять dev-сервер (bun run dev в backend, читает корневой .env). │
│ 3. Получить JWT зарегистрированного пользователя (через существующий /auth/\* флоу или тестовый скрипт с issueToken), затем curl: │
│ - /catalog/categories?type=product — категории по порядку, включая пустые; │
│ - /catalog/cards?type=product&search=ТРАК — регистронезависимый поиск по сид-данным (database/seeds/dev.sql); │
│ - /catalog/cards?type=product&priceType=on_request&categoryId=… — комбинация фильтров; │
│ - пагинация: limit=2&offset=0 → hasMore/nextOffset; │
│ - /catalog/cards/:id архивной карточки → 200 с archivedAt; несуществующий/кривой id → 404; │
│ - без токена → 401; с токеном незарегистрированного → 403. │
│ 4. Ответы должны проходить Zod-схемы контрактов (парсинг в маршрутах это гарантирует).
