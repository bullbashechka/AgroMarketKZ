# AgroMarketKZ — Этапы работ и задачи

Разбивка [PRD.md](./PRD.md) на этапы и задачи под стек шаблона **[di-sukharev/vibe](https://github.com/di-sukharev/vibe)**.

**Стек:** монорепо на Bun.
- `backend/` — Hono + Prisma + PostgreSQL 18 + кастомный JWT + Zod.
- `webapp/` — React + Vite, TanStack Query/Form/Router (CSR за авторизацией) — здесь живёт Telegram Mini App.
- `website/` — Astro (публичные SEO-страницы) — **вне scope** для Mini App, опционально под лендинг.
- `packages/contracts/` — общие Zod-схемы и TypeScript-типы.
- Инфраструктура: Docker Compose (локально), DigitalOcean App Platform (прод), DigitalOcean Spaces (фото), Playwright (E2E).

Условные обозначения: `[ ]` — не сделано. В скобках — ссылки на разделы PRD.

## Этап 1. Модель данных (Prisma + PostgreSQL)

Раздел PRD: 3, 4, 5, 6, 8, 9.

- [ ] Спроектировать схему Prisma:
  - [ ] `User` — telegram id, username, имя из Telegram, сохранённые имя и телефон, признак админа (вычисляется по allowlist).
  - [ ] `Category` — плоский одноуровневый список (раздел 12), название, порядок сортировки.
  - [ ] `Card` (товар/услуга) — название, описание, цена / признак «по запросу», необязательная метка типа (товар/услуга), категория, признак «можно в корзину», флаг видимости цены.
  - [ ] `CardImage` — галерея изображений карточки (несколько фото, порядок).
  - [ ] `CardSpec` — характеристики «ключ — значение».
  - [ ] `CartItem` — позиция корзины пользователя (карточка, количество).
  - [ ] `Request` (заявка/заказ) — источник (`из карточки` / `из корзины`), контакты, комментарий, статус (`новая` / `в работе` / `закрыта`), дата.
  - [ ] `RequestItem` — состав заявки (карточка, количество).
  - [ ] `FeedbackMessage` — сообщение из формы обратной связи.
- [ ] Создать миграции.
- [ ] Сиды: демо-категории и карточки для разработки.

## Этап 3. Авторизация через Telegram (раздел 1, 18)

- [ ] Backend: валидация `initData` Telegram (проверка подписи `TELEGRAM_BOT_TOKEN`).
- [ ] Backend: выдача JWT после успешной валидации, создание/обновление `User`.
- [ ] Backend: middleware авторизации (проверка JWT на защищённых маршрутах).
- [ ] Backend: определение администратора по `ADMIN_ALLOWLIST`, middleware admin-guard.
- [ ] webapp: получение `initData` из Telegram Web Apps SDK, отправка на бэкенд, хранение JWT.
- [ ] webapp: фолбэк для обычного браузера (без Telegram-контекста) — корректная деградация.
